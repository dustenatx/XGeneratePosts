# Decisions

Owner decisions for XGeneratePosts, newest last. The v3 design brief
(provider abstraction) holds the full reasoning; this log records what was
decided, when, and where it departs from the baseline.

| Date | Decision | Why |
|---|---|---|
| 2026-10-20 | **Default provider is Groq; Anthropic stays selectable, unchanged.** `--provider` / `AI_POST_PROVIDER` choose `anthropic`, `groq` or `openai-compat`. | The paid Anthropic key predates the $0 rule. Groq was the only free option covering both the model and the search in one call. The provider abstraction, not the provider, is the protection if a free tier ends. |
| 2026-10-20 | **No search-API source.** Search sources are `native` (the provider searches server-side) and `rss` only. | A third source would add a second vendor, key and free tier for a capability the two paths already cover. The search interface stays open to add one later. |
| 2026-10-20 | **Baseline conversion deferred to v3.1** (departure recorded). v3 does not adopt: uv with a committed lockfile, Typer, Pydantic settings, mypy strict, 85% coverage, `make check` / `make audit`, packaging and release. | v3 is scoped to the provider work plus tests, CI and LICENSE. Until the lockfile lands, CI pins pytest 9.1.1 and resolves its dependencies with `uvx --exclude-newer 2026-10-20`. |
| 2026-10-26 | **Groq model is `openai/gpt-oss-120b` with the `browser_search` tool** (`tool_choice: required`, `reasoning_effort: low`), overridable with `GROQ_MODEL`. Replaces `groq/compound`. | Groq deprecated `groq/compound` and `groq/compound-mini` on 24 Aug 2026 and shut them down on 21 Sep 2026 with no replacement named ([deprecations](https://console.groq.com/docs/deprecations)). Browser Search on GPT-OSS is Groq's documented server-side search ([browser search](https://console.groq.com/docs/browser-search)). Unconfirmed until the first live run: whether the free plan allows `browser_search`, and whether one call fits its 8,000 tokens-per-minute limit. If either fails, run `--provider groq --search rss` and revisit the default. |
| 2026-10-26 | **R20: separate timeouts.** Feed requests 15 s. Provider calls default 120 s via `AI_POST_PROVIDER_TIMEOUT`, which applies to `groq` and `openai-compat` only; the Anthropic SDK keeps its own default. | 15 s is too short for a server-side browser search. Anthropic stays unchanged, and its web search can run long too. |
| 2026-10-26 | **R21: RSS requires Expat 2.7.2 or newer.** Below that, `--search rss` exits naming both versions, and the RSS tests fail rather than skip. | Python's docs say Expat below 2.7.2 may be open to billion-laughs, quadratic-blowup and large-token attacks ([XML security](https://docs.python.org/3/library/xml.html#xml-security)). CI must not pass silently without the RSS tests. |
| 2026-10-26 | **Lint exceptions: `noqa: S310` and `noqa: S314`, each with its reason inline.** S310 on `urllib.request.Request` where the scheme is checked first (https only; plain http only for a localhost openai-compat server). S314 on `xml.etree.ElementTree.fromstring`, behind the Expat check. | R5 allows only the standard library, so `defusedxml` is not an option. Expat 2.7.2+ limits entity amplification and never fetches external resources. Feeds are also capped at 10 MB (R23), and only `identity` encoding is requested (urllib's default), so nothing is decompressed. |
| 2026-10-27 | **R23: feeds get their own 10 MB size cap** (`MAX_FEED_BYTES`). Provider responses keep the 2 MB cap (`MAX_RESPONSE_BYTES`). | In the first live runs, the PostHog and CNCF feeds were over 2 MB and got skipped. |
| 2026-10-27 | **R22: rank and cap RSS candidates.** After the per-feed cap (R19), candidates are ranked by how many distinct topic words (lower-cased, 3+ letters, stop words removed) appear in the title or summary, ties newest first and undated last. At most `AI_POST_RSS_MAX_ENTRIES` are sent (default 20, a whole number of 1 or more). | On 27 Oct, 63 unfiltered candidates plus the profile came to 12,874 tokens, against Groq's free limit of 8,000 tokens per minute, and the call failed with HTTP 413. |
| 2026-10-27 | **R24: 413 and 429 get separate messages** (`groq` and `openai-compat`). 413 says the request is too large for the plan's per-minute token limit and doesn't suggest waiting. With `--search rss` it suggests lowering `AI_POST_RSS_MAX_ENTRIES` or `AI_POST_RSS_PER_FEED`; with native search, `--search rss` with a smaller `AI_POST_RSS_MAX_ENTRIES`. 429 says to wait, with the server's retry-after value when given, and mentions `--search rss` only in native mode. The Anthropic messages are unchanged. | On 27 Oct a 413 told the user to wait and re-run, which can't help a request that is over the limit on its own. Anthropic's 413 is a request-size limit, not a token rate, and R11 keeps Anthropic unchanged. |
| 2026-10-27 | **argparse, not Typer** (departure from the baseline). | The runtime stays standard library only (v3 R5, v3.1 brief section 1). Typer would be the only runtime dependency, for a CLI with a handful of flags. |
| 2026-10-27 | **A small standard-library config module, not pydantic-settings** (departure). One module will read every environment variable in one place; it lands in v3.1 PR 2 with the package. | Same reason: no runtime dependency, nothing at runtime for pip-audit to flag, and the install stays trivial. |
| 2026-10-27 | **`print` for command-line output, not structured JSON logging** (departure). `print` is already a ruff per-file exception (`T201` in `daily_post.py`); `run.log` stays one plain-text line per run. | A personal CLI's output is read by a person, and nothing machine-reads the log. |
| 2026-10-27 | **R29: coverage floor 83%, target 85%** (departure from the baseline's 85%). `make check` fails under 83% (`--cov-fail-under=83`); measured 83.17% on 27 Oct. Raise the floor as coverage grows, up to 85%. **Raised to 85% in v3.1 PR 2**, when coverage moved from `daily_post.py` to the `xgenerateposts` package and measured 86.37% (27 Oct); R29 sets the floor at 85% once the measured figure reaches it. | The floor is the measured figure rounded down. It counts the unit tests only: the acceptance tests run `daily_post.py` in a subprocess with an environment they build themselves, so coverage can't follow them. |
| 2026-10-27 | **R43: the SBOM comes from uv's CycloneDX export** (`uv export --format cyclonedx1.5 --no-dev`, written to `build/sbom.cdx.json` by `make sbom`). uv marks it a preview feature; `--preview-features sbom-export` only silences that warning. If it changes or breaks, the fallback is `cyclonedx-py`. | It reads `uv.lock` directly, so it needs no extra tool. With a standard-library runtime the SBOM lists the package itself and no third-party components; a unit test checks that no dev-only tool appears in it. Same approach as Risk Trainer (24 Oct). **2026-10-28:** from v3.1 PR 3c the SBOM includes the optional extras (`--all-extras`), so it lists the Anthropic SDK and everything it pulls in; `tests/test_sbom.py` checks that `anthropic` appears. |
| 2026-10-27 | **`AI_POST_DATA_DIR` is read after the env file loads**, so setting it in `~/.ai_post_env` works, as the README says. `AI_POST_ENV_FILE` is read only from the process environment. `run()` loads the env file before building the parser, so the `--profile` default uses the same data directory. | Before v3.1 PR 2, `DATA_DIR` was computed at import, before the env file loaded, so `AI_POST_DATA_DIR` in the file was silently ignored. The env file can't name its own location, so `AI_POST_ENV_FILE` inside it stays ignored. Kept as its own commit after the package move, which is behavior-neutral. |
| 2026-10-27 | **Flat layout: the `xgenerateposts/` package sits at the repo root, not under `src/`** (R30). `daily_post.py` is a shim that calls `xgenerateposts.cli.main`. | The frozen acceptance tests run `python daily_post.py`, once with `python -S`. Running a script puts its directory on `sys.path`, so the shim imports the package from the repo root with no install and no site-packages. A `src/` layout would need the package installed first. |
| 2026-10-27 | **Build backend: `uv_build==0.13.1`**, pinned exactly (`module-root = ""` for the flat layout). | It's the same version as the uv that CI pins, so the lock, the build and CI share one toolchain, and it needs no config beyond the module root. On 27 Oct, uv-build 0.13.6 had come out that day and hatchling's latest was 1.32.4 (20 Sep); a release from the same day was skipped. Build requirements aren't in `uv.lock`, so the exact pin is what fixes the version. The wheel holds only the package and its example profile; the sdist adds `pyproject.toml`, `README.md` and `LICENSE`. Neither includes `tests/` or `daily_post.py`. **2026-10-28:** Dependabot moved `uv_build` to 0.13.4 (#11), while CI's uv stays 0.13.1. These are separate packages (the build backend and the uv tool), so the mismatch is harmless. |
| 2026-10-27 | **The example profile lives at `xgenerateposts/author_profile.example.md`, as package data**, and is the only copy. `xgp init` reads it with `importlib.resources`; `tests/test_profile.py` parses the same file. | One source file, so the repo copy and the installed copy can't drift (R33). |
| 2026-10-27 | **R35, R37: security workflow copied from QuestVector** (`.github/workflows/security.yml`, from QuestVector origin/main 205471e). Three jobs, each its own check: `gitleaks` (full history, `--redact`), `semgrep` (`p/default`, `--metrics=off`) and `pip-audit`. Runs on pull requests to master, pushes to master and `workflow_dispatch`. The workflow has `contents: read`; only `gitleaks` and `semgrep` add `security-events: write`, to upload SARIF. Semgrep's in-source suppressions are filtered out of the SARIF before upload, and uploads are skipped for fork PRs. Adapted: branch `master` instead of `main`; `pip-audit` runs `make audit` with ci.yml's setup-uv pin (v10.2.0, uv 0.13.1) instead of QuestVector's export and `audit` group. | Same baseline as Risk Trainer and QuestVector, from a file that already passes there. `make audit` already exports the whole lock with hashes, so one command serves CI and local runs. Every action is pinned to a commit SHA re-checked against its tag (`git ls-remote`) on 27 Oct. Semgrep's `p/default` needs no login. |
| 2026-10-27 | **R36: daily pip-audit on master** (`.github/workflows/audit-daily.yml`, 07:23 UTC plus `workflow_dispatch`). The job is named `pip-audit (daily)` so it can't be confused with the required `pip-audit` check. | A new advisory against a locked version should show up without waiting for a pull request. GitHub's docs: "In a public repository, scheduled workflows are automatically disabled when no repository activity has occurred in 60 days", and runs at the top of the hour can be delayed, hence the off-hour time. If it gets disabled, re-enable it from the Actions tab. |
| 2026-10-27 | **R44: Dependabot version updates** (`.github/dependabot.yml`, copied from QuestVector): `uv` (pyproject.toml and uv.lock) and `github-actions`, weekly, 7-day cooldown, minor and patch grouped per ecosystem, majors on their own. Dusten reviews and merges them like any other PR. | GitHub's options reference lists `uv` as supported and `cooldown` as current (checked 27 Oct). The cooldown applies to version updates only; security updates still arrive as soon as an advisory is published. |
| 2026-10-27 | **The Semgrep image and the gitleaks version are bumped by hand.** Dependabot doesn't update the `semgrep/semgrep` container tag and digest or `GITLEAKS_VERSION` / `GITLEAKS_SHA256` in `security.yml`. A bump re-checks the image digest on Docker Hub and the tarball's sha256 against the release's checksums file. PR 3 keeps QuestVector's 1.179.0 and 8.30.1 (and codeql-action 4.39.0), though Semgrep 1.182.0 and codeql-action 4.39.1 exist. | The image is pinned by digest and gitleaks by checksum, in places Dependabot doesn't read. Staying on QuestVector's versions keeps PR 3 a copy of a setup that already passes. |
| 2026-10-27 | **Semgrep suppression: `python.lang.security.audit.dynamic-urllib-use-detected.dynamic-urllib-use-detected` at `xgenerateposts/publish.py` (`urlopen` in `post_to_linkedin`)**, approved by Dusten. The inline comment uses the suffix `dynamic-urllib-use-detected.dynamic-urllib-use-detected`, on the line before the call. | The Request URL is the literal https://api.linkedin.com/rest/posts, so no `file://` URL can reach it. The full rule ID would put the comment at 103 characters, over ruff's 100; Semgrep matches the suffix to this rule. |
| 2026-10-27 | **Semgrep suppression: `python.lang.compatibility.python37.python37-compatibility-importlib2` at `xgenerateposts/storage.py` (`from importlib import resources`)**, approved by Dusten. | The rule applies only below Python 3.7, and requires-python is >=3.14. |
| 2026-10-28 | **R45: agent rules in `.claude/settings.json`.** Deny: `gh pr merge`, force-push (`--force*`, `-f*`, a `+` refspec), `git commit --amend`, `git rebase`, `git pull --rebase`, `git tag`, `rm -rf` / `-fr` / `-Rf` / `-fR`, edits to `tests/acceptance/` and to `.claude/settings.json`, and reading `~/.ai_post_env`. Ask: every `git push`, `gh pr` and `gh api` call, and any command whose text contains `.ai_post_env`. No allow rules. `tests/test_agent_rules.py` lists every required rule and fails if one is removed or an `allow` key appears. Only Dusten edits the file. | Backs CLAUDE.md's human gates and protected files with rules Claude Code enforces, and ask beats any local "don't ask again". Limit: Bash rules match command text, so another form of the same command (`git -C . push`, `sh -c '…'`, `/bin/rm`, a script) can get past them. They are a guardrail, not a sandbox; the ruleset and the human gates remain the controls. `*.ai_post_env*` is an ask, not a deny: it matches the name anywhere in a command, so a deny would also block commit messages, PR bodies and greps that only mention the file. Reading the file itself stays denied by `Read(~/.ai_post_env)`, which covers the file tools and `cat`, `head`, `tail` and `sed`. |
| 2026-10-28 | **R46: SBOM as a workflow artifact** (`.github/workflows/sbom.yml`). Each push to master, and `workflow_dispatch`, runs `make sbom` and uploads `build/sbom.cdx.json` as `sbom-<commit SHA>`, kept 90 days. `contents: read`, actions pinned to SHAs; not run on pull requests. | The artifact is the interim home for the R43 SBOM until R39 attaches it to each release in PR 4. |
| 2026-10-28 | **R47: `SECURITY.md`.** Reports go through GitHub private vulnerability reporting; scope is key handling, what the profile sends to providers, feed and redirect handling, the draft-only default and `xgp init` file modes; only the latest commit on master is supported. Turning on private vulnerability reporting is Dusten's step. | Gives reporters a private channel and says what's in scope. Adapted from QuestVector's policy. |
| 2026-10-28 | **R48: optional extra `anthropic = ["anthropic==2.3.0"]`**, pinned exactly in `pyproject.toml` and nowhere else. `dependencies` stays empty, so the default install is still standard library only (R5). Install routes, from the repo clone: `uv tool install --reinstall '.[anthropic]'` for the installed `xgp`, and `~/.ai_post_venv/bin/pip install -e '.[anthropic]'` for a clone's venv. The missing-package message names the extra and both routes, never a version. The mypy override for the lazily imported SDKs stays. | 2.3.0 is the version in the venv that ran `--provider anthropic` successfully on 27 and 28 Oct (installed 27 Oct). With no version in the messages, the README or the docstring, a Dependabot pin bump needs no text edits. `pip install -e` works with `uv_build` (checked 28 Oct in a scratch venv), and `daily_post.py` still imports the clone's package first. A later `uv tool install --reinstall .` without the extra drops it. httpx2 2.16.0 declares `httpx2-jsfetch` 1.0 only for `sys_platform == "emscripten"` (Pyodide), so it never installs on macOS or Linux. It is in `uv.lock`, the SBOM and the audit because uv locks for every platform, and its PyPI page lists no project links. |
| 2026-10-28 | **Same-week packages accepted in the extras lock**, with no constraint-dependencies: anthropic 2.3.0 (uploaded 23 Oct), jiter 0.18.0 (23 Oct), and httpx2 and httpcore2 2.16.0 (21 Oct). certifi 2026.10.23 (23 Oct) was on the first list, through tweepy. | The four are the set that ran with `--provider anthropic` on 27–28 Oct. certifi 2026.10.23 was already in `uv.lock` on master through the dev tools, so this PR doesn't introduce it. Since the `x` extra was deferred, no extra pulls it in (it isn't in the SBOM), and Dependabot will keep it current. |
| 2026-10-28 | **R48: the `x` extra (tweepy) is deferred; only the `anthropic` extra ships.** `--post` keeps the hand install, `~/.ai_post_venv/bin/pip install tweepy`, in a clone's venv. Revisit when tweepy allows oauthlib>=4. | tweepy 4.17.0, the current release, requires `oauthlib<4`, and oauthlib 3.3.1 has CVE-2026-49264, CVE-2026-49265 and CVE-2026-49272, fixed in 4.0.0. A grep of the tweepy 4.17.0 and requests-oauthlib 2.0.0 wheels showed only client-side oauthlib use (OAuth1 signing and the OAuth2 client classes), none of the affected server code. But posting has never run, and the required `pip-audit` check shouldn't carry an exception. Re-locking without `x` removed tweepy, oauthlib and requests-oauthlib from `uv.lock`. |
