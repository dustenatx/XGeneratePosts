# Decisions

Owner decisions for XGeneratePosts, newest last. The v3 design brief
(provider abstraction) holds the full reasoning; this log records what was
decided, when, and where it departs from the baseline.

| Date | Decision | Why |
|---|---|---|
| 2026-10-20 | **Default provider is Groq; Anthropic stays selectable, unchanged.** `--provider` / `AI_POST_PROVIDER` choose `anthropic`, `groq` or `openai-compat`. | The paid Anthropic key predates the $0 rule. Groq was the only free option covering both the model and the search in one call. The provider abstraction, not the provider, is the protection if a free tier ends. |
| 2026-10-20 | **No search-API source.** Search sources are `native` (the provider searches server-side) and `rss` only. | A third source would add a second vendor, key and free tier for a capability the two paths already cover. The search interface stays open to add one later. |
| 2026-10-20 | **Baseline conversion deferred to v3.1** (departure recorded). v3 does not adopt: uv with a committed lockfile, Typer, Pydantic settings, mypy strict, 85% coverage, `make check` / `make audit`, packaging and release. | v3 is scoped to the provider work plus tests, CI and LICENSE. Until the lockfile lands, CI pins pytest 9.1.1 and resolves its dependencies with `uvx --exclude-newer 2026-10-20`. |
| 2026-10-26 | **Groq model is `openai/gpt-oss-120b` with the `browser_search` tool** (`tool_choice: required`, `reasoning_effort: low`), overridable with `GROQ_MODEL`. Replaces `groq/compound`. | Groq deprecated `groq/compound` and `groq/compound-mini` on 24 Aug 2026 and shut them down on 21 Sep 2026 with no replacement named ([deprecations](https://console.groq.com/docs/deprecations)). Browser Search on GPT-OSS is Groq's documented server-side search ([browser search](https://console.groq.com/docs/browser-search)). Unconfirmed until the first live run: whether the free plan allows `browser_search`, and whether one call fits its 8,000 tokens-per-minute limit. If either fails, run `--provider groq --search rss` and revisit the default. |
| 2026-10-26 | **R20: separate timeouts.** Feed requests 15 s. Provider calls default 120 s via `AI_POST_PROVIDER_TIMEOUT`, which applies to `groq` and `openai-compat` only; the Anthropic SDK keeps its own default. | 15 s is too short for a server-side browser search. Anthropic stays unchanged, and its web search can run long too. |
| 2026-10-26 | **R21: RSS requires Expat 2.7.2 or newer.** Below that, `--search rss` exits naming both versions, and the RSS tests fail rather than skip. | Python's docs say Expat below 2.7.2 may be open to billion-laughs, quadratic-blowup and large-token attacks ([XML security](https://docs.python.org/3/library/xml.html#xml-security)). CI must not pass silently without the RSS tests. |
| 2026-10-26 | **Lint exceptions: `noqa: S310` and `noqa: S314`, each with its reason inline.** S310 on `urllib.request.Request` where the scheme is checked first (https only; plain http only for a localhost openai-compat server). S314 on `xml.etree.ElementTree.fromstring`, behind the Expat check. | R5 allows only the standard library, so `defusedxml` is not an option. Expat 2.7.2+ limits entity amplification and never fetches external resources. Feeds are also capped at 10 MB (R23), and only `identity` encoding is requested (urllib's default), so nothing is decompressed. |
| 2026-10-27 | **R23: feeds get their own 10 MB size cap** (`MAX_FEED_BYTES`). Provider responses keep the 2 MB cap (`MAX_RESPONSE_BYTES`). | In the first live runs, the PostHog and CNCF feeds were over 2 MB and got skipped. |
| 2026-10-27 | **R22: rank and cap RSS candidates.** After the per-feed cap (R19), candidates are ranked by how many distinct topic words (lower-cased, 3+ letters, stop words removed) appear in the title or summary, ties newest first and undated last. At most `AI_POST_RSS_MAX_ENTRIES` are sent (default 20, a whole number of 1 or more). | On 27 Oct, 63 unfiltered candidates plus the profile came to 12,874 tokens, against Groq's free limit of 8,000 tokens per minute, and the call failed with HTTP 413. |
| 2026-10-27 | **R24: 413 and 429 get separate messages** (`groq` and `openai-compat`). 413 says the request is too large for the plan's per-minute token limit and doesn't suggest waiting. With `--search rss` it suggests lowering `AI_POST_RSS_MAX_ENTRIES` or `AI_POST_RSS_PER_FEED`; with native search, `--search rss` with a smaller `AI_POST_RSS_MAX_ENTRIES`. 429 says to wait, with the server's retry-after value when given, and mentions `--search rss` only in native mode. The Anthropic messages are unchanged. | On 27 Oct a 413 told the user to wait and re-run, which can't help a request that is over the limit on its own. Anthropic's 413 is a request-size limit, not a token rate, and R11 keeps Anthropic unchanged. |
| 2026-10-27 | **argparse, not Typer** (departure from the baseline). | The runtime stays standard library only (v3 R5, v3.1 brief section 1). Typer would be the only runtime dependency, for a CLI with a handful of flags. |
| 2026-10-27 | **A small standard-library config module, not pydantic-settings** (departure). One module will read every environment variable in one place; it lands in v3.1 PR 2 with the package. | Same reason: no runtime dependency, nothing at runtime for pip-audit to flag, and the install stays trivial. |
| 2026-10-27 | **`print` for command-line output, not structured JSON logging** (departure). `print` is already a ruff per-file exception (`T201` in `daily_post.py`); `run.log` stays one plain-text line per run. | A personal CLI's output is read by a person, and nothing machine-reads the log. |
| 2026-10-27 | **R29: coverage floor 83%, target 85%** (departure from the baseline's 85%). `make check` fails under 83% (`--cov-fail-under=83`); measured 83.17% on 27 Oct. Raise the floor as coverage grows, up to 85%. **Raised to 85% in v3.1 PR 2**, when coverage moved from `daily_post.py` to the `xgenerateposts` package and measured 86.37% (27 Oct); R29 sets the floor at 85% once the measured figure reaches it. | The floor is the measured figure rounded down. It counts the unit tests only: the acceptance tests run `daily_post.py` in a subprocess with an environment they build themselves, so coverage can't follow them. |
| 2026-10-27 | **R43: the SBOM comes from uv's CycloneDX export** (`uv export --format cyclonedx1.5 --no-dev`, written to `build/sbom.cdx.json` by `make sbom`). uv marks it a preview feature; `--preview-features sbom-export` only silences that warning. If it changes or breaks, the fallback is `cyclonedx-py`. | It reads `uv.lock` directly, so it needs no extra tool. With a standard-library runtime the SBOM lists the package itself and no third-party components; a unit test checks that no dev-only tool appears in it. Same approach as Risk Trainer (24 Oct). |
| 2026-10-27 | **`AI_POST_DATA_DIR` is read after the env file loads**, so setting it in `~/.ai_post_env` works, as the README says. `AI_POST_ENV_FILE` is read only from the process environment. `run()` loads the env file before building the parser, so the `--profile` default uses the same data directory. | Before v3.1 PR 2, `DATA_DIR` was computed at import, before the env file loaded, so `AI_POST_DATA_DIR` in the file was silently ignored. The env file can't name its own location, so `AI_POST_ENV_FILE` inside it stays ignored. Kept as its own commit after the package move, which is behavior-neutral. |
| 2026-10-27 | **Flat layout: the `xgenerateposts/` package sits at the repo root, not under `src/`** (R30). `daily_post.py` is a shim that calls `xgenerateposts.cli.main`. | The frozen acceptance tests run `python daily_post.py`, once with `python -S`. Running a script puts its directory on `sys.path`, so the shim imports the package from the repo root with no install and no site-packages. A `src/` layout would need the package installed first. |
| 2026-10-27 | **Build backend: `uv_build==0.13.1`**, pinned exactly (`module-root = ""` for the flat layout). | It's the same version as the uv that CI pins, so the lock, the build and CI share one toolchain, and it needs no config beyond the module root. On 27 Oct, uv-build 0.13.6 had come out that day and hatchling's latest was 1.32.4 (20 Sep); a release from the same day was skipped. Build requirements aren't in `uv.lock`, so the exact pin is what fixes the version. The wheel holds only the package and its example profile; the sdist adds `pyproject.toml`, `README.md` and `LICENSE`. Neither includes `tests/` or `daily_post.py`. |
| 2026-10-27 | **The example profile lives at `xgenerateposts/author_profile.example.md`, as package data**, and is the only copy. `xgp init` reads it with `importlib.resources`; `tests/test_profile.py` parses the same file. | One source file, so the repo copy and the installed copy can't drift (R33). |
